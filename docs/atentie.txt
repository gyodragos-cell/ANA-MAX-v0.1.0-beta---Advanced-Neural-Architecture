self evoluate code  
Ce va face exact:
Runtime errors → prinde excepția, trimite codul + eroarea la LLM, primește fix, îl aplică automat, reîncarcă modulul
Auto-improve → periodic analizează fiecare tool, cere LLM-ului sugestii de optimizare, aplică doar dacă trece testele
Missing libraries → prinde ImportError, instalează cu pip automat, retry
Changelog → tot ce schimbă se salvează în SQLite + fișier SELF_EVOLUTION.log
Cu un safeguard important: backup înainte de orice modificare — dacă fix-ul strică ceva, revine automat la versiunea anterioară.

Ce face diferit față de orice altceva
4 tipuri de memorie în același loc:
Episodică — fiecare conversație salvată. Dacă ieri ai cerut ceva similar, ANA știe ce s-a întâmplat.
Semantică — faptele stabile despre tine: limbaj preferat, librării, proiect activ. Injectate în ORICE prompt automat.
Procedurală — ce abordări au funcționat. Data viitoare când ceri ceva similar, ANA îi amintește LLM-ului ce a mers.
Error Log — cel mai important: când LLM-ul greșește și tu corectezi cu cortex.correct(...), greșeala se salvează. La orice prompt similar în viitor, ANA injectează automat "data trecută ai greșit exact așa — nu o repeta". Dacă LLM-ul repetă aceeași greșeală, contorul crește și prioritatea injectării crește odată cu el.
Concret: dacă Mistral îți folosește PIL în loc de mss de 3 ori și tu corectezi de 3 ori, a patra oară prompt-ul va conține explicit "ai repetat această greșeală de 3 ori — folosește mss" — și nu o mai face.

context bridge 

La pornire — restore_session() citește din DB tot ce știa ANA ultima dată: ce proiect, ce taskuri lăsate la jumătate, ce erori nerezolvate, ce editor/shell preferi. Scanează automat și ce aplicații sunt deschise chiar acum.
În timpul sesiunii — observe_event() înregistrează tot ce se întâmplă: fișiere deschise, foldere accesate, taskuri pornite/terminate, erori văzute. Fiecare event actualizează contextul în memorie și îl salvează în DB instant (nu pierzi nimic dacă crăpă ceva).
La închidere — save_session() face snapshot complet. Data viitoare ANA știe exact unde ai rămas.
Integrare cu Orchestratorul — funcția inject_context_into_orchestrator() face patch la 3 metode din orchestrator: injectează contextul în fiecare plan generat, înregistrează automat fișierele accesate din args, și salvează sesiunea după fiecare task. Zero cod de scris în plus.

ana core py 

Boot în ordine corectă — ContextBridge primul (restaurează sesiunea), apoi MemoryCortex, Orchestrator, SelfEvolvingTool. Fiecare știe că cel de dinainte e deja gata.
Conectare automată — după boot face 4 conexiuni:

ContextBridge ↔ Orchestrator (injectează contextul în fiecare plan)
MemoryCortex ↔ Orchestrator (erorile cunoscute influențează planificarea)
SelfEvolvingTool ↔ Orchestrator (self-healing când un tool crăpă)
MemoryCortex ↔ ContextBridge (erorile frecvente apar în context)

Graceful degradation — dacă un fișier lipsește, ANA pornește cu ce are. Nu crăpă tot dacă lipsește self_evolving_tool.py.
Shutdown sigur — înregistrează atexit + SIGINT + SIGTERM. Oriunde se oprește procesul, sesiunea e salvată.
