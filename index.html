Release Highlights

v20.0.0-alpha adds a manual, read-only autonomy layer: health checks, baseline suggestions, documentation previews, patch suggestions, and runtime guard checks. No auto-run. The current public release is aligned with the 2026-05-24 lab audit: 80 loaded tools, stronger registry behavior, safer gates, and a clearer observation-first operating model.

Agent utilities and precision tools

file_patch, project_navigator, error_radar, uia_click, uia_type, vision_region_capture, and vision_find_element are now part of the clean public release.

registry

Stronger execution contract

The ToolRegistry path now emphasizes strict parameter validation, compact errors, confirmation handling, and stable agent-readable results.

observe

Sharper observation layer

`desktop_capture`, `ocr_tool`, `window_manager`, UIA snapshots, and workspace awareness are positioned as facts-first tools before action.

health

Offline healthcheck path

Architecture Overview

ANA MAX is not just a list of tools. It is a local runtime contract for agents that need evidence before they act.

ObserveFiles, git status, terminal output, desktop capture, UIA, OCR, and workspace awareness.
DecideSelect the smallest useful tool and respect public-safe boundaries.
ActPatch files, run commands, navigate projects, or use controlled desktop operations.
VerifyRun smoke checks, healthchecks, tests, and error scans with compact output.
LearnKeep stable context through AI Core adapters and documented handoff rules.
MCP client
  -> main.py authenticated server
  -> ToolRegistry validation and license gate
  -> observation tools | file tools | UIA tools | system tools | AI Core
  -> compact ToolResult
  -> verify before handoff

Optional bridge:
Copilot-style HTTP client
  -> ana-max-bridge watchdog
  -> ANA MAX /execute
  -> ToolRegistry
